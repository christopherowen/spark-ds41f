01 · Native weights

The model DeepSeek shipped.

Most ways of fitting a big model on small machines start by changing the model. This one starts by leaving it alone. The checkpoint is DeepSeek's, at its published precision, with its own tokenizer; the work goes into the engine around it.

Nothing re-quantized

The published FP8, FP4 and BF16 weights load directly from the checkpoint. No distillation, no community re-quant, no "close enough" build.

Split, never altered

Tensor parallelism shards every layer across three to eight Sparks. The cables carry the partial sums; the arithmetic follows DeepSeek's reference.

The whole feature set

Full 1M-token context, vision, tool calls, reasoning effort, DeepSeek's own speculative drafter, and an OpenAI-compatible API that also speaks DeepSeek's dialect.

02 · Correct first

Fast and wrong is just wrong.

A speed-up is only a speed-up if the answers did not move. Every change is measured as an experiment, the unfavourable runs are kept, and nothing is promoted until it passes the same gate as the release before it.

    03 · Then fast

    Then make it quick.

    With the answers pinned down, speed becomes an engineering problem you can grind on. These are the changes that moved the numbers most, each one landed as a measured experiment against the release before it.

    04 · weightle.ss

    Steering built in, weights untouched.

    Native weights does not mean one fixed personality. The server speaks weightless: a small GLP vector steers the model per request, beside the stock model, on the same engine.

    One server, two names, zero copies.

    Ask for the stock name and you get DeepSeek's model, bit for bit. Ask for the weightless name and the same loaded weights are steered by msuiche's published GLP vector for that request only. Nothing is merged, nothing is duplicated in memory, and turning it off is a matter of using the other name.

    09 · Start

    Cable it. Check it. Start it.

    You need three or more DGX Sparks and the cables between them. The tools print a plan before they touch anything, and refuse to start a cluster whose cabling, kernel or image does not match the recipe.

    Quick start on GitHub → Full setup guide 
    # name your cabling once
bin/spark site shape tp4-ring --apply

# reports only; prints each fix as a command
bin/spark doctor

# a plan until you say --apply
bin/spark --cluster-config config/cluster.json \
  cluster start --apply
