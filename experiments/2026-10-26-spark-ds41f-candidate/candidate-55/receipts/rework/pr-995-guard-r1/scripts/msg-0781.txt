fix(spec_decode): guard negative slots in copy_alloc and copy_apply

Base: candidate-54 vLLM patch head 4e8133ff10a125b90753c2727f162e29fe37f30c (tree 5f021d9a7f01c03e2389dd3d8021759cfa19ea34). The slot guard of #995 (head aa65752e9864, patch 0762-perf-spec-decode-copy-drafter-guards-and-wide-ramp.patch on 1107 vLLM patch head 2756478b60b9), alone, reworked for candidate-55.

Rationale:
copy_match_kernel reads total_len[slot] and history[slot] only for slot >= 0, whereas copy_alloc_kernel and copy_apply_kernel indexed total_len[slot], int_state[slot], float_state[slot] and history[slot] unconditionally: a negative idx_mapping entry would read and write the row before each tensor. Guard slot >= 0 in both. For a negative slot, copy_alloc_kernel writes no copy (chosen (-1, 0, 0), the prior estimate PRIOR_HITS / PRIOR_TRIALS, alloc = block) and reads and writes no per-slot state; copy_apply_kernel takes DSpark's drafts and clears no per-slot state, whatever chosen holds.

Serving effect: none. No serving path passes a negative slot to copy_alloc or copy_apply. GPUModelRunner.sample_tokens passes input_batch.idx_mapping to CopyDrafter.prepare_alloc and propose; prepare_inputs builds it from req_states.req_id_to_index (slots from free_indices, range(max_num_reqs)) and InputBatch.make_dummy as arange(num_reqs). The copy path's only -1 rows, match_idx_mapping's for requests still mid-prefill, go to copy_match alone, which already guards them. Pipeline parallelism's -1 entries (PPHandler.get_prev_sampled_outputs) reach postprocess_sampled only, and copy_calls only declares the kernels for compilation. The guard is a robustness fix for direct callers of the kernels.
