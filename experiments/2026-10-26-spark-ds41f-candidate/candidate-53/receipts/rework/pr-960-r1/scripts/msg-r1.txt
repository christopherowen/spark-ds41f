perf(cudagraph): capture target FULL attention/CED metadata replay and deduplicate DFlash padding

Upstream base: 1107 vLLM patch head 2756478b60b90700b9918b457aeb38657da637b5 (tree ed1bdb7a7684da33d403a055521ac0c4dd7ca670).

Rationale:
1. On every CUDAGraphMode.FULL target decode step in 1107, GPUModelRunner.execute_model unconditionally invoked build_slot_mappings_by_layer (90-layer dict) and model_state.prepare_attn, which allocated two fresh pinned host tensors via torch.tensor(..., pin_memory=True) in CEDState.stage, issued two H2D copies, launched ced_kernels.requests(..., compact=False) eagerly, and looped over all 23 target KV-cache groups to launch 23 separate tl_metadata.builder kernels eagerly from Python (~420-436 us/step), even though run_fullgraph and DFlashSpeculator.propose ignore the returned attn_metadata and slot_mappings_by_layer dicts.
   - Extend ModelCudaGraphManager.capture to record model_state.prepare_cudagraph_replay (invoking ced_kernels.requests(..., compact=False) in-graph) and each attention group builder's prepare_cudagraph_replay inside every CUDAGraphMode.FULL target graph when can_capture_full_attn_metadata holds.
   - Skip build_slot_mappings_by_layer and model_state.prepare_attn on runtime CUDAGraphMode.FULL steps when captures_full_attn_metadata is active, staging only changed CED replay floors through a preallocated 4-slot pinned host ring buffer in CEDState.stage_floors (~390 us/step saved).
2. In DFlashSpeculator.propose, tilelang_inputs.padding_rows(self._is_padding, live, num_tokens_padded) was launched eagerly between _context_preparer.run and query_cudagraph_manager.run_fullgraph on every step even when live was unchanged from the previous step. Track _padding_live and skip the redundant kernel launch when live is unchanged (~12 us/step saved).

Quality implications:
None. Both changes preserve bit-identical outputs (torch.equal across all decode shapes at temperature=0) and add zero GPU memory overhead.

Round 1:
- Fixed the boot failure. The FULL fast path's condition in GPUModelRunner.execute_model called self.kv_connector.has_connector(). No KVConnector in this base has that method (neither the no-op base class that NO_OP_KV_CONNECTOR instantiates nor ActiveKVConnector; upstream vLLM's has none either; the only has_connector in the tree is KVTransferConfig.has_connector(connector_name)). The first runtime FULL step, the warm-up decode step (warmup._run_decode_step), raised AttributeError on every rank, and candidate-53 did not boot at tp3-switched. The condition now reads `self.kv_connector is NO_OP_KV_CONNECTOR`: get_kv_connector returns that instance when no KV transfer group exists (the serving case) and an ActiveKVConnector otherwise, whose pre_forward reads the step's attention metadata. The fast path still runs only when no KV connector is active, as intended. NO_OP_KV_CONNECTOR is already imported by the runner.
- Audited every attribute the patch's non-test lines read against this base: has_connector was the only one missing. The others exist (BlockTables.cp_size, AttentionGroup.get_metadata_builder, DeepseekV41B12xMetadataBuilder.prepare_cudagraph_replay, DefaultModelState.prepare_attn, InputBuffers.query_start_loc/seq_lens, BlockTables.input_block_tables/slot_mappings, ced_kernels.requests(compact=), DeepseekV41ModelState._ced_rows) or the patch adds them.
- Added tests/v1/worker/test_gpu_model_runner_v2.py::test_full_cudagraph_decode_attn_prep_follows_kv_connector: it runs GPUModelRunner.execute_model on a FULL decode step up to model-input preparation, with the connector get_kv_connector returns. With NO_OP_KV_CONNECTOR the step only stages CED floors (stage_full_cudagraph_attn); with an ActiveKVConnector it builds the eager metadata (build_slot_mappings_by_layer, prepare_attn). Before this fix both cases raise AttributeError.
- No other change: ced.py, model_state.py, cudagraph_utils.py and the DFlash speculator are as before. Applies as 0781 in candidate-53's series (0782..0785 after it) with git am; git diff --check clean.
- Measured on GB10 (sp8): spark-ds41f:candidate-50 with the corrected candidate-53 files mounted. A one-GPU run of the warm-up decode step's pre-forward segment (GPUModelRunner.execute_model from its first line to model-input preparation, with the real get_kv_connector, the real DeepseekV41ModelState CED staging, DSpark's class and can_capture_full_attn_metadata on 23 real B12x builder groups) reproduces the original's AttributeError at model_runner.py:3204 and passes with this fix: NO_OP_KV_CONNECTOR stages only the CED floors and its in-graph CED refresh equals an eager CEDState.stage; an ActiveKVConnector builds the eager metadata.
