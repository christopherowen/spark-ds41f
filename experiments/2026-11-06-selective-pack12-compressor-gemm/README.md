# Selective 12-bit (`pack12`) Lossless BF16 Compressor GEMM (`#838` Rework)

## Metadata
- **Date**: 2026-11-06
- **Deployment base commit**: `239fad99b6a48104a8bc7a14f66d1f730b58ee94`
- **vLLM base commit**: `a75357bba81e31e4f3085700f94b6a0b29aed44a` (Candidate `1107`)
- **vLLM candidate commit**: `bda03b50997f7fd7b7b84f90f8425cb082f7d94f` (`feat/pack12-compressor`)
- **Patch file**: `0001-perf-dsv41-pack-compressor-BF16-weights-to-12-bit-se.patch`
- **Hardware**: `dgx4` (NVIDIA GB10, 2 fresh container boots of `spark-ds41f:candidate-43`)
- **Intended causal variable**: Selectively and unconditionally apply lossless 12-bit (`pack12`) BF16 weight compression to `compressor.fused_wkv_wgate` (`TileLangSplitLinearMethod`), while keeping L2-hot/prefetched `router.gate` (`[384, 5120]`, `TileLangLinearMethod`) and `indexer.weights_proj` (`[32, 5120]`, `TileLangScaledLinearMethod`) in uncompressed BF16.

## Rationale & Design
1. **Selective application (`TileLangSplitLinearMethod` only)**:
   - Previously, `#838` (`0847f5cf0`) applied `pack12` to `TileLangLinearMethod` (`router.gate` `[384, 5120]`) and `TileLangScaledLinearMethod` (`indexer.weights_proj` `[32, 5120]`) in addition to `compressor.fused_wkv_wgate`. Because `router.gate` and `indexer.weights_proj` are tiny and L2-prefetched/L2-hot, the unpack compute overhead regressed `router.gate` by `2.25x-3.72x` warm (`+472 us/step` across 61 layers).
   - By applying `pack12` exclusively to `TileLangSplitLinearMethod` (`compressor.fused_wkv_wgate`), `router.gate` and `indexer.weights_proj` incur zero overhead while `compressor.fused_wkv_wgate` gets `-25%` weight memory and DRAM traffic across all layers.
2. **Prologue exception-range binary search + lean 9-arg SWAR `__byte_perm` inner loop**:
   - `vllm_packed_bf16_filter_exc` runs once in the CTA prologue before `T.Pipelined`: when `num_exceptions == 0` (the common case for standard normal-range BF16 weights), it exits immediately without reading `row_offsets`; when `num_exceptions > 0`, it binary-searches `exception_entries[row_offsets[r]..row_offsets[r+1]]` to `[col_start, col_end)`.
   - Inside `T.Pipelined`, `vllm_packed_bf16_decode_vec16` unpacks 32 BF16 values per call via `uint4` loads and `__byte_perm` with register-only CSR exception patching (`STACK:0` verified across all 68 cached cubins).
3. **Occupancy-aware staging (`SPLIT_BF16`) across all TP1/TP3/TP4..TP8 compressor shard shapes**:
   - Supports both `parts = 2` (`compress_ratio = 2`, `out_dtype = float32`: `N = 1024, 384, 256, 128`) and `parts = 1` (`compress_ratio = 1`, `out_dtype = bfloat16`: `N = 512, 192, 128, 64`) at `K = 5120`.
   - High-CTA grids (`tiles_N * shards > 40`: `N in {1024, 512, 384}`) use `single_b = blocked` and 2-stage pipelining for `3-4` CTAs/SM occupancy; narrower shards (`N in {256, 192, 128, 64}`) use `B0_shared + B1_shared` (`single_b = False`) and 3-stage `cp.async` pipelining.
4. **Medium-prefill split-K routing (`_split_rows`) + warp-per-row coalesced `packed_bf16_unpack`**:
   - Routes `rows <= _split_rows(layer)` (`256` for `N > 128`, `512` for `N <= 128`, fitting inside the existing `(N, K)` BF16 prefill scratch budget) through `packed_bf16_gemm_splitk[64]`, avoiding intermediate `weight_scratch` materialization and beating uncompressed `bf16_gemm` by up to `1.63x-2.79x` warm and `1.02x-1.08x` cold-washed at `M = 256`.
   - For larger prefill (`rows > _split_rows(layer)`), `packed_bf16_unpack` maps one 32-thread warp to 8 contiguous K-groups (`1,024` columns) of the same row for 100% coalesced global reads/writes before launching `bf16_gemm` / `bf16_gemm_two`.

## Memory Savings
- **TP1 / Replicated (`N = 1024`, `K = 5120`, `parts = 2`)**: `10.00 MiB -> 7.50 MiB` per layer (`-2.50 MiB/layer`, `-105.0 MiB` across 42 MLA layers or `-152.5 MiB` across 61 layers).
- **TP3 Padded Shard (`N = 384`, `K = 5120`, `parts = 2`)**: `3.75 MiB -> 2.8125 MiB` per layer/rank (`-0.9375 MiB/layer/rank`).
- **TP4 Shard (`N = 256`, `K = 5120`, `parts = 2`)**: `2.50 MiB -> 1.875 MiB` per layer/rank (`-0.625 MiB/layer/rank`).
- **TP8 Shard (`N = 128`, `K = 5120`, `parts = 2`)**: `1.25 MiB -> 0.9375 MiB` per layer/rank (`-0.3125 MiB/layer/rank`).
- **TP1 / TP3 / TP4 / TP8 `parts = 1` (`N = 512, 192, 128, 64`)**: exact `-25.0%` weight storage reduction (`5.00 -> 3.75 MiB`, `1.875 -> 1.406 MiB`, `1.25 -> 0.9375 MiB`, `0.625 -> 0.46875 MiB`).
